Three graph nodes: Orchestrator → Parse Agent → Orchestrator → Response Agent → Orchestrator → END. “Respond” above is a tool step inside the Response Agent, not a fourth graph node.

Inside parsing: parse_query uses keyword rules. validate_and_refine_parsed_query checks scope using an LLM. Rejected questions end before retrieval.

Inside the response loop: The model returns a tool name and arguments; Python executes the tool with inputs from shared state. This app constrains each request to the next permitted tool and one call at a time. Order and limits are enforced in code.

Retries: Policy search requests 5, then 10, then 15 candidates and appends up to five unseen chunks per attempt. Only NOT_RELEVANT increments the attempt. Policy evidence alone is validated. Cases are retrieved once. Three failed validations produce an insufficient-evidence response.

Observability: Live runs can trace graph nodes, tools, model requests, inputs, outputs, latency, and available token usage in your LangSmith project. Tracing sends question and excerpt content to LangSmith when enabled. Demo fixtures never call external models or LangSmith.
